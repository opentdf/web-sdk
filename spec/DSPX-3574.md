# Make web-app sample OIDC/DPoP flow compliant and recommendable

## Summary
BackgroundThe web-sdk's web-app/ directory carries two roles in tension:
CI integration test — Playwright tests that demonstrate end-to-end SPA integration with the SDK against a live platform.
Reference implementation for application developers — the closest thing we ship to a "this is how you wire OpenTDF into a React app" sample.
These goals pull in opposite directions. As a CI fixture we want it self-contained and full of escape hatches; as a sample we want it to be small, idiomatic, and copy-pastable.
Symptomweb-app/src/session.ts contains an OidcClient class with its own implementations of the OIDC code flow, DPoP proof generation, and a withCreds(httpReq) method — duplicating logic that already lives in lib/src/auth/{oidc,interceptors,dpop}.ts.
This duplication drifted: the recent RFC 9449 §7.1 fix (use DPoP Authorization scheme for DPoP-bound tokens, not Bearer) had to be applied separately to lib/src/auth/oidc.ts AND web-app/src/session.ts:527. The lib fix alone did not fix the web-app, because the web-app never went through the lib's auth code. A future SDK developer fixing a similar bug would almost certainly miss the second site.
Why this mattersDPoP is a security-positive but ergonomically-expensive feature. Every integration step we ask of an app developer is a chance to get it wrong in a way that's silently insecure (e.g. shipping a DPoP-bound token under Bearer, which lenient resource servers will accept until they don't). The sample app is the artifact developers will copy. If the sample bypasses the lib's correctness, every copy of the sample inherits the bypass.
Desired outcomeRefactor web-app/src/session.ts so that it:
Consumes the lib's published auth primitives (AccessToken / authTokenDPoPInterceptor / dpop) instead of re-implementing them.
Contains only the SPA-specific glue that the lib can't provide: redirect handling, session storage, React state wiring.
Is short enough to be a good sample (today it's ~500 lines, much of which is auth re-implementation).
This both eliminates the drift class of bug AND makes the sample a more credible "do it like this" reference.
Acceptance criteriaweb-app/src/session.ts no longer duplicates token exchange, DPoP proof generation, or withCreds-shaped logic that exists in @opentdf/sdk/auth.
All Playwright tests in web-app/tests/ still pass against a live platform.
The dpop-headers Playwright test (added in web-sdk @ 2296fb1f) still passes, asserting DPoP scheme + header on the rewrap.
A README note in web-app/ explains the sample's dual role and explicitly directs implementors to copy from this file as their starting point.
Out of scope (track separately if needed)Splitting the CI test harness from the sample app entirely (two directories instead of one). Could be a follow-up if the refactor proves they can't peacefully share a home.
Publishing the sample as an npm-installable starter template.
ReferencesDrift bug that motivated this: the DPoP-scheme fix needed parallel changes in lib/src/auth/oidc.ts:321 and web-app/src/session.ts:527
Parent platform fix landed in DSPX-3397 branch; SDK fix in web-sdk DSPX-2399 branch
Related: DSPX-3573 (platform: reject Bearer for DPoP-bound tokens)
