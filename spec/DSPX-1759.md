# Modernize the TypeScript + ESLint toolchain across web-sdk (lib, cli, web-app)

## Summary
SummaryThe opentdf/web-sdk repo has drifted well behind current TypeScript/ESLint practice. All three packages pin TypeScript ~5.8, none of them declare eslint as a direct dependency (so each resolves a different ESLint major transitively), and every eslint.config.mjs is a mechanical FlatCompat translation of the old .eslintrc format. lib/ — the published @opentdf/sdk — still compiles with strict: false.
This ticket covers bringing the compiler, lint, and format toolchain up to current standards across lib/, cli/, and web-app/.

eslint is not a direct devDependency in any package. Each one lints against whatever version floats up through the dependency graph — currently three different majors, with lib/ (the published SDK) on ESLint 8.57.1, which is end-of-life. Lint results are therefore not reproducible and not consistent between packages.
ESLint config problemsAll three eslint.config.mjs files are FlatCompat shims around the legacy config format:
They compat.extends("plugin:@typescript-eslint/recommended", "plugin:prettier/recommended") instead of using the native flat exports (tseslint.configs.recommended, eslint-plugin-prettier/recommended). FlatCompat + @eslint/eslintrc should not be needed at all here.
cli/eslint.config.mjs and web-app/eslint.config.mjs never set a TypeScript parser — no parser: tsParser. They rely entirely on whatever the compat layer happens to install.
Both declare ecmaVersion: 5 with sourceType: "commonjs" (cli) and sourceType: "script" (web-app), for codebases that are ESM and TSX respectively.
parserOptions.project: ["**/tsconfig.json"] is a recursive glob in all three. This should be projectService: true, which is both faster and correct for files outside the project graph.
lib/eslint.config.mjs imports globals and @eslint/eslintrc, but lib/package.json declares neither. It only works via node_modules hoisting.
No type-aware linting anywhere (recommendedTypeChecked / strictTypeChecked), despite project already being configured.
tsconfig problemslib/tsconfig.json sets strict: false and then hand-rolls a partial subset (strictNullChecks, strictFunctionTypes, strictBindCallApply, alwaysStrict), with strictPropertyInitialization: false. noUnusedParameters, noFallthroughCasesInSwitch, useUnknownInCatchVariables, and noUncheckedIndexedAccess are all absent.
web-app/tsconfig.json is strict: true, so strictness is inconsistent across the repo.
No modern module-correctness flags anywhere: verbatimModuleSyntax, erasableSyntaxOnly, moduleDetection, exactOptionalPropertyTypes.
target / lib are es2021 in lib/ and cli/, while .nvmrc is Node 24.
lib/tsconfig.json sets baseUrl: "./" with no paths — vestigial, and baseUrl is on the way out.
cli/tsconfig.json extends ../lib/tsconfig.json and overrides module to Node16 while lib uses NodeNext. It also inherits composite, declaration, and declarationDir: "./dist/types"; verify where that declarationDir actually resolves, since relative paths in an extended config resolve against the file that declares them (i.e. possibly lib/dist/types).
.nvmrc says 24 but AGENTS.md / CLAUDE.md document Node 22.
Scope1. Pin and unify ESLint. Add eslint as an explicit devDependency in all three packages at the same major. Bump @eslint/js to 10.x and typescript-eslint to 8.70+.
2. Rewrite the three flat configs by hand. Drop FlatCompat and @eslint/eslintrc entirely; use tseslint.config(...) with the native flat presets. Set the correct sourceType/ecmaVersion per package, wire the TS parser explicitly in cli/ and web-app/, and switch to projectService: true. Add the missing globals / plugin devDeps that the configs actually import.
3. Enable type-aware linting. Adopt recommendedTypeChecked at minimum. Expect a batch of new findings — triage into fix-now vs. tracked follow-ups rather than blanket-disabling rules.
4. TypeScript upgrade, staged. Land on the last 5.x first, then clear deprecations under 6.x, then evaluate 7.x (tsgo, the Go-native compiler) as a separate step. A direct jump to 7.0.2 is explicitly not the plan for this ticket — see Risks.
5. Turn on strict: true in lib/. Remove the hand-rolled flag subset. Add noUnusedParameters, noFallthroughCasesInSwitch, and verbatimModuleSyntax. Treat noUncheckedIndexedAccess and exactOptionalPropertyTypes as stretch goals — they are high-churn and can be split out if the diff gets unwieldy.
6. Housekeeping. Raise target/lib in line with the supported Node and browser matrix, drop the vestigial baseUrl, reconcile the cli/ → lib/ tsconfig inheritance, bump Prettier, and fix the Node version drift between .nvmrc and AGENTS.md.
Acceptance criteriaeslint is an explicit devDependency at a single shared major across lib/, cli/, and web-app/; npm ls eslint in each resolves to that version.
No package imports @eslint/eslintrc or FlatCompat.
Every module a config imports is declared in that package's package.json.
make lint passes clean in all three packages, with type-aware rules enabled.
lib/tsconfig.json has strict: true and no compensating per-flag opt-outs beyond ones with a comment explaining why.
make test passes: lib (mocha + web-test-runner + karma, coverage thresholds intact), cli (mocha), web-app (vitest), and web-app/tests (Playwright).
The published artifact is unchanged in shape: dist/web, dist/cjs, and dist/types all still emit, and every exports subpath in lib/package.json still resolves.
Any rule suppressed rather than fixed has a follow-up ticket linked here.
RisksPublished .d.ts surface. @opentdf/sdk ships declarations that downstream consumers compile against. Turning on strict can change emitted types (notably nullability). Diff dist/types before and after and treat any change as potentially breaking.
Dual CJS/ESM build. lib/ runs tsc twice (tsconfig.json + tsconfig.commonjs.json) plus scripts/add-module-types.sh. verbatimModuleSyntax and any module change interact directly with this; validate both outputs.
TypeScript 7 / tsgo. Fast, but it is a distinct implementation with known gaps, and this repo leans on composite + declaration emit and a custom second CJS pass. This is why the upgrade is staged rather than a single jump.
Type-aware lint cost. Enabling projectService + typed rules will slow CI lint. Measure it; the win from dropping the **/tsconfig.json glob may offset it.
Blast radius. This touches the build for a published SDK. Per repo convention it warrants an explicit risk call-out in the PR description.
NotesPrefer landing this as several reviewable PRs (lint config rewrite → TS bump → strictness) rather than one large one. Repo convention is Conventional Commits with the ticket key, e.g. chore(sdk): enable strict mode in lib (DSPX-1759).
Fix-only lint churn should be isolated from behavioral changes, per AGENTS.md.
